## 2. 验证码识读（本脚本的关键难点）

验证码图 **108×40 PNG**，三层颜色：

| 层 | 颜色 |
|---|---|
| 背景 | 蓝 `RGB(0,153,204)` |
| **文字** | 深灰蓝 `RGB(84,114,124)` |
| 干扰线 / 噪点 | 浅灰 `RGB(168,168,169)` |

**三步净化**（比单纯按颜色分离有效得多）：

1. **取非背景**：`|pixel - (0,153,204)|.sum() > 60` → 得到文字+干扰线+噪点
2. **去长横段**：同一行连续 `> 14` 像素的段判为干扰线，抹掉（字符宽度约 12px，不会误伤）
3. **连通域过滤**：只保留 `>= 25` 像素的连通块（字符），孤立噪点全消

**三步净化已脚本化**：`scripts/u2_captcha_clean.py /tmp/u2_captcha.png` —— 输出逐字点阵 + 7× 放大黑字白底图（`/tmp/u2_captcha_big.png`，发用户代读用）。

⚠️ **补充第 4 步：斜线密度过滤** —— 第 ② 步只抹「同一行连续」的**横线**，**对角线干扰会幸存并穿越字符**（把单字切分连成一段）。做法：连通域过滤时把「宽度 >20 且 密度 = 面积/(w*h) < 0.2」的细长块判为干扰线一并剔除（字符密度 ~0.5，不会误伤）。

净化后输出**黑字白底 6~7 倍放大图**，再交给视觉模型或用户读。

**经验**：
- 视觉模型对这张图**不可靠**（实测把 `AQ6g` 读成 `ACg`，漏了中间两位）。
- **净化图发给用户读是最稳的**：用户一眼就给出正确 `AQ6g`。所以：自己读两次不中就发净化图请用户读，别硬赌。
- 2026-09-30 从零全流程实测：邮箱+密码 → 图形验证码（净化图请用户读 `NXYA`，视觉曾读 `DXYA` 首字分歧）→ NEED_2FA（用户手递 6 位动态码）→ 登录成功；20/20 尝试次数未损。
- 2026-09-30 实测补充：净化放大图上**视觉模型仍会与用户读分歧**（模型 `DXYA` vs 用户 `NXYA`，分歧在易混字形 D/N）——分歧时不值得多轮仲裁，`RELOAD` 换一张更便宜；以用户读为准。
- 中间有被干扰线切断的位置是正常的，不要当成两个字符。
### 2.1 为什么不训练识别器（结论）＋交回方式（并入自 `u2-captcha.md`）
- 站点每张图**随机换字体 + 换字号**：15 字体 × 12 字号 × 62 字符 = 11,160 种字形；可靠识别需 ≈13,950 张样本，且瓶颈在标注（人工不行、模型不行、字体反推需先知道字体＝循环依赖）。
- 实测：自建识别器 62.2% 逐字 / 33% 整张全对（库覆盖 1.9%），性价比极差，代码已删。**结论：不做识别；「净化图 → 用户读」是最短路径。**
- 交回方式：净化图发用户读（Telegram 发图）→ 用户回复字符 → 作为 `--stage2 <验证码>` 位置参数传入。⚠️ **不要再写 `/tmp/u2_captcha_answer.txt`**（那是已归档浏览器版轮询的文件，现行 `u2_http.py` 不读；它只有 2FA 码入口 `/tmp/u2_2fa_code.txt`）。
- 换一张读：重跑 `--stage1` 取新图（随机字体下换图比多轮仲裁便宜）；别依赖答案文件的 `RELOAD` 约定。视觉与用户读分歧（易混字形）以用户读为准。
- 历史方案「恢复会话备份（cookie 有效期 ~400 天）」：仅确有备份时适用；**本机例行不做全量备份（2026-09-27 用户要求删除全部备份）→ 当前无备份**，难登录站一律走完整登录流程。


## 3. 每日签到（`showup.php`）

首页用户栏的 **`[立即签到]`** 指向 `showup.php`。

### 不是点一下就完 —— 要解图像题

```
签到区
  在此写下留言（至少 5 个字符）
  CAPTCHA：请找出左侧图片中圆点，再选择该处对应的作品名称
  本测试有效期 120 秒
  回答正确 → 9~59 个 UCoin 随机；回答错误 → 1 个 UCoin
```

表单 `POST showup.php?action=show`：

| 字段 | 说明 |
|---|---|
| `_csrf` | hidden |
| `message` | textarea，**≥5 字符**（如「签到打卡，感谢分享！」） |
| `req` / `hash` / `form` | hidden |
| `captcha_<md5>` ×4 | **4 个 submit 按钮 = 4 个候选作品名**，`value` 就是作品名（每局随机 md5） |

题目图：`image.php?action=adbc2&req=v2.<hex>`，**500×354**，左右两块动画封面，一个小圆点标在其中一块上；图上有 `VALID BEFORE <时间> CST` 水印。

### 旧脚本：`scripts/u2_showup_signin.py`（已归档；签到并入 `u2_http.py --stage3/--stage4`）

- 抓题 + 抓 4 个选项 → 打印 `PUZZLE_READY {png, round, options}` → 轮询 `/tmp/u2_puzzle_answer.txt`
  - 写 **`RELOAD`** → 重开页面换一题
  - 写**序号 1-4** 或作品名片段 → 填留言 + 点对应 `captcha_<md5>` 按钮
- 复核：用户栏 `[已签到]` + 「感谢，今天已签到。」+ 签到记录里出现自己的条目（`奖励UCoin: N`）

### 解题要点

- **视觉模型能解**（实测一次答对：圆点在《劇場版総集編ハイキュー!!》海报上 → 选项 1，拿到 26 UCoin）。问法：把 4 个候选名一起给模型，让它判断圆点标在哪个上。
- **圆点定位（2026-09-30 实测，最稳路径）**：圆点 = 实心**绿圆**（本次约 57px、填充率 0.77 ≈ 标准圆），压在其中一块封面的一角（本次在右封面右下角）。先用**本地绿色连通域扫描**定位：`g > r+25 且 g > b+25 且 g > 110`，取 ≥30px、近方形（长宽差≤6）、fill≥0.6 的块 → 按中心 x<250/≥250 判左右；再把**圆点所在侧封面**的描述连同 4 个候选名交给视觉模型辨认作品名。纯让视觉「找圆点」不稳——不加专项问题描述时模型会漏报圆点，必须明确问「圆点在左还是右」。绿点定位已脚本化：`scripts/u2_dot_locate.py <png>`（输出圆点坐标与所在侧）。
- **两块封面都可能就在 4 个候选名单里**（实测左=长腿叔叔、右=海のオーロラ，两块都是候选项）——答案永远是**圆点所指的那块**；不找圆点、按「这块我认识」直接猜，等于 50/50 硬赌。
- 题目 **120 秒过期**，过期算签到失败（**不算答错**，不扣 UCoin），`RELOAD` 换一题即可。
- 过期时间可从图上水印直接读：`VALID BEFORE <HH:MM:SS> CST`（CST=UTC+8，比本地 CEST 快 6 小时）= 出题后 120 秒。答不出来时别耗在来回确认，直接 `RELOAD`。
- 答错只拿 1 UCoin，代价很小；但**别把 120 秒耗在来回问用户上**，自己判一次优先。
- 签到记录页会公示每人的「CAPTCHA正确答案」，可用来验证格式。

- **登录入口 = 站点自带的「Legacy Devices」页 `portalbc.php`**（专为无 JS 设备准备，页面无任何前端脚本）：GET 即得 `form-login` 表单，字段 `login_type=email`（hidden）/ `username`=邮箱 / `password` / `otp_code` / `captcha`；验证码图 `captcha.php?sid=<hex>` 可直接 urllib 下载（**108×40 PNG，与 `u2_captcha_clean.py` 同规格**）。⚠️ 不发 `logout` / `securelogin`。
- 四段式（cookie：`~/.pt-sessions/state/u2_cookies.txt`）：
  - `--stage1` 导出验证码 → `CAPTCHA_READY`；
  - `--stage2 <验证码> <2FA>`（2FA 亦可写 `/tmp/u2_2fa_code.txt` 由脚本轮询）→ 提交登录；
  - `--stage3` 抓 `showup.php` 题面（`_csrf` / `message` / `req` / `hash` / `form` + 4 个 `captcha_<md5>` 按钮）→ `PUZZLE_READY` + `/tmp/u2_puzzle.png`；
  - `--stage4 <序号1-4 或作品名片段>` 提交（留言自动填「签到打卡，感谢分享！」）。⚠️ **别按 `--stage4` 的输出判成败**：成功时它也可能打「签到结果: 未见明确标记」并回显页面里的 `window.location.href = 'https://u2.dmhy.org/showup.php'`——那是站点自身的跳转语句，不是失败信号。**唯一判据 = 重跑 `--stage3`，看是否出现 `✅ 今天已经签到过：[已签到]`**。另注意站点「答错也只给 1 UCoin、签到照样消费」，所以 `[已签到]` 只证明保活达成，不证明答案选对。
- 圆点定位仍用 `scripts/u2_dot_locate.py`（纯本地）；120 秒时限不变，换题 = 重跑 `--stage3`。复核判据与浏览器版一致（用户栏 `[已签到]` / 签到记录 `奖励UCoin: N`）。
