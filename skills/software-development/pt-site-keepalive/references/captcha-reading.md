# 图形验证码识别（PT 站通用）

**自己读，不要一上来就丢给用户**（用户明确表达过不满）。两路交叉：ASCII 点阵 + 视觉模型。一致就直接提交；不一致时点阵优先（不依赖模型）；只差一两位时按视觉取一个再验。**验证码读错通常不扣登录次数**，可以放心重取重读。

## 1. 按图型选分离法（先看像素，别直接上灰度阈值）

| 图型 | 特征 | 做法 |
|---|---|---|
| NexusPHP `regimage` 彩色噪点 | 文字是**纯黑 `RGB(0,0,0)`**，噪点是彩色（如 `(237,150,150)` `(176,219,120)`） | `g = np.array(im.convert('L')); dark = g < 100` —— 噪点全被滤掉，字符非常干净 |
| 低饱和深色文字 + 同亮度灰噪点 | 文字不是纯黑，噪点里混有与文字亮度相近的灰点（如 HDSky） | 多滤一层饱和度：`mx = a.max(axis=2); mn = a.min(axis=2)` → `mask = ((mx - mn) < 60) & (mx < 150)`。只用 `g < 100` 时灰噪点会跟着文字一起留下，点阵里全是孤点、没法读 |
| 高噪点 + 干扰线 | 背景噪点密 + 横线穿过字符 | 三步净化：① 取非背景色像素；② 抹掉同一行连续 >14 像素的长横段；③ 连通域过滤只留 ≥25 像素的块。净化后放大成黑字白底再读 |
| 渐变色背景 | 背景亮度逐列变化，全局阈值失效 | 逐列背景估计 `bg = np.percentile(a, 85, axis=0)`，取 `(bg[None,:] - a) > 18` |

彩色噪点图直接用灰度阈值分割会被噪点淹没 —— 这是白花时间的第一步。

## 1b. 散点噪点图：**先去噪再切分** —— `scripts/captcha_clean.py`

随机黑点满图飞时，按列切分会出虚段（空白噪点段、字间黏连），逐字点阵里也全是孤点。先把噪点滤掉再切分：

```bash
/usr/bin/python3 scripts/captcha_clean.py /tmp/xxx_captcha.png      # 默认 2 轮去噪
```

原理：每轮只保留「有 ≥2 个 8 邻域邻居」的像素 —— 笔画（2~3px 粗的连续块）全部保留，孤立散点全被滤掉。去噪后重新切列、逐字打印，字符是干净的 8~10px 笔画图，逐字判读几乎不会错。实测 Audiences / HDSky / CHDBits 三张图，去噪点阵与视觉模型**独立给出完全一致的读数**、全部一次通过；OpenCD 与 CHDBits 的登录码（混合「纯黑文字 + 彩色块 + 散点黑噪」图型）同样一次双路一致（`3G772E` / `PPNDNB`）。⚠️ **这类带散点黑噪的图不要从 `captcha_dotmatrix.py` 开始试**：散点会把分段黏成 20+px 宽的虚段（字间连体、读不出），直接 `captcha_clean.py` 起步，逐字干净、与视觉一次对上。

⚠️ **裁剪仲裁的坐标必须以去噪后的切分为准**：散点的虚段会把真字符挤进错误区间 —— 据噪声切分裁区域，会得出「这段没有字符」之类的错结论（实测把真实存在的字符裁丢、误判尾部无字符；去噪后重切即见）。

## 2. 点阵打印规范（三条，缺一条就会读错）

```python
from PIL import Image; import numpy as np
im = Image.open(png); w, h = im.size
a = np.array(im.convert('L')).astype(int)
print('     ' + ''.join(str((x // 10) % 10) if x % 10 == 0 else ' ' for x in range(w)))  # 列标尺
for y in range(h):
    row = ''.join('#' if a[y, x] < 100 else '.' for x in range(w))
    if row.count('#') >= 3:
        print('%3d %s' % (y, row))
```

- **覆盖整幅宽度**（`range(w)`）：写成 `range(20, 130)` 之类的局部窗口会把最右侧字符**整位丢掉** —— 实测把 6 位验证码读成 5 位，白提交一轮。
- **带列标尺**：每 10 列标一位，字符边界靠「有像素的列间隙」切分，比凭感觉数点快得多。
- **只印有效行并保留行号**：行号用来判断「上环 / 腰部 / 下环」，是下面判别表的基础。

## 3. 字形判别表（按笔画结构判，不靠整体印象）

| 易混 | 判据 |
|---|---|
| 6 vs 8 | 看**腰部行**：6 的腰部**右侧留空**（右上是开口弧），8 腰部两侧都有像素 |
| 8 vs B | **左侧恒定直竖、右侧是弧 → B**；两侧都是弧 → 8；B 的上下横更宽 |
| 9 vs 4 | 9 = 上部闭合环 + **右侧**竖到底；4 = 左上斜线收成尖点 + 中横 + 右侧竖 |
| A vs 4 | 看中横以下：A 仍**向两侧张开**，4 只剩**右侧**竖 |
| R vs P | R 的腿在环下方右侧**仍有斜/竖笔画**；P 没有；B 应有底部闭合横 |
| C vs G | 看**右侧中段**：C 的右缘在腰部几行**完全空白**（只在顶/底有弧），G 的右侧从头到尾有竖笔、底部内折成横。只比顶部会把 C 读成 G |
| 0 vs O | 0 窄长（椭圆），O 更圆；常需裁单字放大定夺 |
| S vs 3 | S 的**上段与下段左缘各有一段竖笔**；3 的左侧只在上下弧的**最左端点**有孤立像素，中段是向右折返的锯齿、右侧自上到下连续。裁单字时两者易分歧，按「左侧有没有竖笔段」定案 |
| 9 vs g/q | **比基线**：该字底缘不越过其他字符的共同基线 → 9（弯尾 9 的底缘与数字同高）；明显越过基线（有降部）→ g/q。⚠️ 单字裁剪会失去基线参照，视觉会把弯尾 9 判成 g —— 定案必须回整图对比各字底缘行号。再补一条**环顶高度**：环顶与同排大写（C/K 等）齐平 → 9；明显更矮（只到 x 高度）→ q。基线 + 环顶合判最稳 |
| S vs 9 | 看**左下角**：S 的底弧在左下收出字尾（左下方几行有渐次小笔画）；9 的左下为空、右侧竖一插到底。该字体下两者形状接近、视觉常把 S 读成 9 —— 冲突时按此结构差异用点阵定案 |
| K vs X/R | K：左竖**贯穿全高**、上臂自右上斜入杆中、下臂自杆中向右下斜出；X 无贯穿竖杆（两斜线交叉）；R 的右上应是**闭合碗形**且顶部与竖杆相连（不检查顶部连接处会把 K 误读成 R） |
| 3 vs G/e | 3：左侧只有上下弧**端点**的孤离像素、中段全空；G：左侧同 C 一样**连续**、且腰右有内折横杠；e：中横与上弧闭合成上环（中横不闭合 → 3） |

**单字歧义**：裁该字符单独放大 12~14 倍，点阵字体用 **NEAREST**（比 LANCZOS 更清）。

**两路分歧时的定案手法：裁出「争议的那 1~2 个字」单独打印纯黑点阵**，不要在整图点阵上反复比对 —— 整图行多字密，肉眼容易把相邻字符的笔画算进当前字。窗口取「争议字符 ± 半个字宽」，并另存一份 NEAREST 放大 8 倍的裁剪图给视觉模型复核；**两边重新一致再提交**。实测一张图第 3~4 字（真值 `CC`）在整图点阵里被读成 `GG`，裁出 x∈[56,94] 单独打印后一眼定案。

**别把「草率点阵」当裁决器**：点阵只有在逐字符切分、谨慎判读时才有裁决力。实测整图粗扫的点阵把 `NEM6C9` 读成 `HEHOC8`（前两位就错），而同一张图经**去噪去边框、放大 6 倍**后视觉模型读得完全正确 —— 冲突时先看净化图质量，净化到位就信视觉。

## 4. 时效与两阶段等待

- 冷启动 Camoufox 要 30~40 秒，单轮「启动 → 取图 → 人读 → 提交」经常来不及。
- **浏览器常驻 + 脚本循环**（每轮 reload 取新图重试），并让**脚本自己打印点阵**（脚本内 `subprocess` 调系统 python + PIL），把「取图 → 读数 → 提交」压到一次工具往返。
- ⚠️ **提交窗口 <2 分钟的图（HDU 类 memcached 存储）要把「就绪 → 提交」压进 ≤2 次工具调用**：① 一次合并「轮询等图出现 → 立即净化打印」；② 直接写答案；**窗口内不做视觉二次复核**（每个来回 20~60 秒）。实测 HDU：36.8s 提交 ✅、113.7s 报「图片代码无效」已失效。
- 脚本用 `background=true` 跑，打印 `CAPTCHA_READY` 后**阻塞轮询答案文件**；动态码同理（打印 `NEED_2FA` + 码文件）。「先要码、再开浏览器」的单阶段做法一定把码耗掉。
- **具体文件名**：通用脚本 `nexusphp_login.py` 用 `/tmp/nx_<site_key>_captcha.png`（另有 `_clean.png`）+ 答案 `/tmp/nx_<site_key>_captcha.txt` + 动态码 `/tmp/nx_<site_key>_2fa.txt`。写答案前先 `grep` 脚本确认，别猜。
- ⚠️ **外层 `timeout` 要大于「浏览器冷启动 + 人读验证码」**：脚本内部等答案的窗口是 1800s，但外面套 `timeout 600` 会在验证码刚生成时把进程杀掉，表现为「跑到一半凭空退出」。用 `timeout 2400` 或不套。
- ⚠️ **不要用 `| tail -N` 包住长跑脚本**：管道缓冲会让你在脚本已打印 `CAPTCHA_READY` 时仍看到空白，极易误判「卡死」并杀掉一个已经跑到要码步骤的进程。看进度只看进度文件和进程存活。
- 同一 `imagehash` 每次请求都返回**新图**（连取两次 md5 就不同）→ 只能读「刚取到的那张」，不能缓存复用。
- 收工时**顺手删掉答案文件**，防止残留进程继续提交、白扣次数。

## 5. 读不准时的升级顺序（不要跳步、也不要无限换模型）

1. 点阵 + 视觉并行，一致即提交；**散点噪点图把去噪版点阵（`scripts/captcha_clean.py`）当点阵路**（原版在虚段多时会漏字、误裁）。
2. 不一致或存疑：把**净化图放大 6 倍**再给视觉（视觉的强项是净化图，不是原始噪点图）。
3. 自己连读错两次：把净化图**发给用户读**（实测 U2 的 4 位码视觉两次都错，用户一眼给出正确值）。
4. **视觉链暂时不可用（503/超时）时不要卡整条流程**：去噪点阵单路读，逐字笔画结构完整可辨即可提交（多数站验证码错不扣次数）；视觉恢复后再回到两路交叉。
5. **现成净化脚本**：黑字图（HDU/PTHOME 类，可能带黑边框）用 `scripts/captcha_clean_blacktext.py <png> [hdu|pthome]`（剔除贴边连通域去边框 + 逐字切分 + 6× 放大图）；散点噪点图用 `scripts/captcha_clean.py`；U2 蓝底干扰线图用 `scripts/u2_captcha_clean.py`；U2 签到题绿点定位用 `scripts/u2_dot_locate.py`。
