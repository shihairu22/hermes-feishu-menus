# 朱雀 ZHUQUE（`zhuque.in`）

**游戏化**私有 PT（TNode 框架：Vue SPA + Ant Design + Node/express-session），前置 Cloudflare（无 JS 挑战，HTTP 200 直放）。
凭据**与馒头一致**（`PTUSER`）；**开了二步验证**，验证码发到馒头的 QQ 邮箱（可自动 IMAP 读取）。

## 1. 登录：纯 API 流程（表单会被 Ant Design 校验拦住）

```
① GET /entry/login
     → 从 <meta name="x-csrf-token" content="..."> 取 CSRF（32 位）
     → 会话 cookie: socute

② POST /api/user/send2fa   {username, password}
     {}                    → 401 INVALID_USERNAME
     {username}            → 401 WRONG_PASSWORD     ← 必须带密码！
     {username, password}  → 200 SEND_2FA_SUCCESS
     上一码未过期          → 401 LAST_2FA_VALID     ← 互斥保护

③ 读邮箱：主题「登录二步验证码 - 朱雀」，正文：
     「…验证码：4d318521，有效期十分钟」
     ★ 验证码是 8 位十六进制（a-f0-9），不是纯数字！

④ POST /api/user/login     {username, password, _2fa: <code>}
     → 200 LOGIN_SUCCESS
```

### 三个必踩的坑

1. **不要走页面表单**：Ant Design 表单的 `_2fa` 是必填项，不填码时点「登 录」**不会发任何请求**（表单校验直接拦下），容易误判为“按钮失效”。
2. **验证码是 8 位 hex**：邮件里是 `验证码：4d318521`。用 `\d{4,8}` 抓数字会截成 `318521` → 报 `INVALID_2FA`。正确提取：`验证码[：:]\s*([A-Za-z0-9]{6,12})`。
3. **`LAST_2FA_VALID`**：上一码 10 分钟内仍有效时不给新码。处理：直接回读最近一封朱雀邮件里的码（注意算年龄，别用过期的）。

附带好处：`send2fa` 会校验凭据（密码错返回 `WRONG_PASSWORD`），**不消耗登录次数就能验账号密码**。

脚本：`scripts/zhuque_login.py`（含上面全部处理）；持久档案 `~/.pt-sessions/zhuque-login-session`。
成功判据：`LOGIN_SUCCESS` + `/api/user/getInfo` 返回 `status:200`。

★★ **所有 `/api/gaming/*` 请求必须带 `x-csrf-token` 头**（2026-09-27 实测）：

未升级角色（`level:null`）可释放但 **bonus=0**。
批量释放成功返回 `{"code":"FIRE_GENSHIN_CHARACTER_MAGIC_SUCCESS","bonus":N}`。

**例行做法**：跑 `scripts/zhuque_gaming.py`（已含 CSRF 处理 + 冷却判定 + 只读式复查），
只调 `{all:1}` 批量接口，**不做遍历等待**（技能 3/4 释放后不更新 `next_time`，遍历会死循环）。

技能类型：`1 获得灵石` / `2 灵石加成` / `3 免除冷却` / `4 双倍灵石`。
**注意**：技能 3、4 释放后**不更新 `next_time`**，遍历等待会死循环（社区脚本踩过），必须设最大重试次数。

## 五、★ 释放技能的收益最大化（2026-09-28 实测计算）

### 实测数据（116 个角色全部 lv=79）

- **削减倍率分布**：`{10%: 74 个 · 25%: 16 个 · 100%: 26 个}`
- 单次释放基础值：`200 + 120×(等级-1)`，lv79 = **9,560**；满级 90 = **11,000**
- **全部释放一轮**：名义 1,108,960 → 实际 **357,544**（平均只拿到 32.2%）
- **冷却分布**：0-6h: 2 · 6-12h: 6 · 12-24h: 102 · >48h: 6（多数为 12~24 小时）

### 核心结论

1. **释放会使 `累计收益` 上升 → 比值变大 → 倍率继续下滑**。
   所以每个角色会随时间从 100% → 50% → 25% → 10%，这是**单向的**。
2. **但不释放 = 0 收入**，所以「释放」永远优于「不释放」。
   **不存在「攒着以后放」的玩法**（收益即时结算，无积累加成）。
3. **最优释放策略**：
   - ① **冷却一结束就释放**（空转即纯损失）
   - ② **优先释放高倍率角色**（26 个满倍率角色贡献约 70% 的收益）
   - ③ **释放频率比释放时机重要**
4. **建议：把释放从「每天 1 次」改为「每 8 小时 1 次」**
   - 每天 1 次时平均空转约 6 小时 → 损失约 25% 潜在收益
   - 每 8 小时 1 次可将空转降到约 2 小时 → 日收入从约 35.8 万提升到 43~45 万灵石（+20~25%）
   - 成本仅为多两次浏览器启动（约 4 分钟），零风险
5. **持续增益型技能（`magic` 为 3/4）要择时释放**：
   释放后一段时间内提升「上传/下载/灵石」计算，应在**即将大量下载或做种前**释放，
   空闲时释放等于浪费。`magic` 为 1/2 的是「提升数据型」，立即到账，无需择时。

### 升级的性价比（回答「要不要升到 90」）

以 10% 档角色为例（lv79，cost 1,022,028，profit 3,830,700）：

| 操作 | 倍率变化 | 每次多赚 | 回本所需释放次数 |
|---|---|---|---|
| 再投入 50 万 | 10% → 25% | +1,434 | 349 次 ✗ |
| 再投入 100 万 | 10% → 50% | +3,824 | 262 次 ✗ |
| 升到 90（+39 万） | 10% → 25%，且基础值 +15% | +1,794 | 220 次 ✗ |

- 每天约 1 次释放 → **回本需 7~12 个月**。
- **结论：短期不值得 ✗；长期（数年）才划算 ✓。**
- **26 个满倍率角色升到 90 最划算**（吃满全额 +15%，不受削减）✓。

### 接口备忘

- 释放：`POST /api/gaming/fireGenshinCharacterMagic {all:1, resetModal:true}`（批量）或 `{id}`（单个）
- **必须带 `x-csrf-token`**（否则返回极具误导性的「请清空缓存及本站 Cookie 后重试」）
- 角色数据：`GET /api/gaming/listGenshinCharacter` → `data.characters[].info.{level,next_time,cost,profit,ratio}`
- **逐个升级 `{id, level:90}` 会返回 `400 LEVEL_IS_90`**（带 id 时 level 语义与批量模式不同），
  要按角色升级目前只能用批量模式 `{resetModal:false, level:N}`（作用于全部已拥有角色）。

- 实现：`scripts/zhuque_release.py`（状态文件 `~/.pt-sessions/state/zhuque_buff_state.json`

  → `CHANGE_BIND_GENSHIN_CHARACTER_SUCCESS`
- **行秋/班尼特自己不需要释放**（它们只影响绑定对象）

### ③ 每 8 小时自动释放（cron）
