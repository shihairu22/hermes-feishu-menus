# 例行「签到pt」的暂停 / 续跑 / 报告口径

> 2026-10-03、2026-10-04 两轮实测总结（用户两次中途叫停）。

## 用户叫停（「暂停」「停下」「你在干嘛」）

1. **先停再解释**：立刻 `kill` 掉批次脚本与子进程（`batch*.sh`、`*_http.py`、`*_login.py`、`camoufox`、`Xvfb`），再用 `ps` 复核为空，然后才回复。
2. **已完成站点要补录**：叫停生效前往往还有 1~2 站跑完（日志里已有 `EXIT=0` 与结果行），必须逐站 `record_checkin.py --site … --status ok --note …` 补进去；只报「停下时的进度」会漏站、报错数字（实测 21:56 那轮：口头以为 4 站，实际 6 站）。
3. **不要 `--finish`**：给本轮 note 写「用户 HH:MM 叫停 —— 本轮暂停（已完成 N 站，可续跑）」，`ended` 留空。下一轮 `--begin` 会自动补结束时间，卡片上也不会一直挂着。
4. 只取到验证码图、未提交登录的站（如 `--stage1` 之后被叫停）**不计入**已完成，零消耗，续跑时重来即可。

## 续跑

- 继续往**同一轮**追加站点即可（`record_checkin.py --site …` 会写进未结束的那一轮）。
- **不要重新 `--begin`**：那会开新轮，进度显示从 0 起，用户会以为白跑了。

## 记账小坑

- `record_checkin.py --site` 的站名含空格（`SJTU 葡萄`）**必须整体加引号**：不加会被 argparse 拆成两个参数，报 `unrecognized arguments: 葡萄`，该站静默漏记（实测漏过一次，进度数字直接少 1，用户会按 29 站核对）。
- 批次驱动脚本写进 scratch 目录（如 `cache/scratch/pt_run_<日期>/batch1.sh`），串行 run + 每站前后各写一行带时间戳日志；暂停、续跑、取证都只看这一个日志文件，也不必让长跑输出进上下文。

## 报告口径

- 用户说「只看失败的」→ 收尾时**只列 fail/异常站**（含未完成站），成功站不逐条播报，但一律照常写进 `checkin_runs.json`。
- 用户没这么说时按技能正文：逐站简报，长跑期间主动播报进度。
- 中途叫停时，回复格式：先说「已停、无进程」，再给「本轮已完成 N 站」清单 + 剩余站数。
